🔗 Битрикс24 — Интеграция

Как получить: Битрикс24 → Разработчикам → Другое → Входящий вебхук → Создать.
Обязательные права:
• task — создание/чтение задач (tasks.task.add, task.checklistitem.add)
• user — список сотрудников (user.get)
• disk — файлы Диска (disk.folder.getchildren, disk.file.get) — для импорта ТО
• crm — опционально, для привязки задач к CRM (UF_CRM_TASK)
Формат URL: https://ваш-домен.bitrix24.ru/rest/USER_ID/SECRET/
USER_ID — от имени этого пользователя будут создаваться задачи (CREATED_BY)
Сотрудники из Битрикс24
Нажмите «Загрузить» для получения списка сотрудников
Список используется для назначения ответственных (RESPONSIBLE_ID) и наблюдателей (AUDITORS) в задачах ТО.
API: user.get → поля: ID, NAME, LAST_NAME, WORK_POSITION, UF_DEPARTMENT
Импорт регламента ТО из Битрикс24 Диск
Как это работает:
1. Загрузите регламент ТО (PDF/DOCX) на Диск Битрикс24
2. Укажите ID папки → SCADA сканирует файлы
3. Выберите файл → AI-агент транскрибирует документ
4. Результат автоматически создаст интервалы и чеклисты ТО
API: disk.folder.getchildren → disk.file.get → AI parse
Автоматическое создание задач при наступлении ТО
Поля задачи tasks.task.add:
• TITLE — заголовок по шаблону
• DESCRIPTION — описание с работами ТО (BBCode)
• RESPONSIBLE_ID — ответственный (из настроек объекта)
• CREATED_BY — постановщик (USER_ID из webhook URL)
• AUDITORS — наблюдатели (массив ID)
• GROUP_ID — проект/группа
• DEADLINE — срок в ISO-8601: 2025-01-15T19:00:00+03:00
• PRIORITY — 0/1/2 (низкий/средний/высокий)
• ALLOW_CHANGE_DEADLINE — N (запрет сдвига срока)
Чеклист task.checklistitem.add:
• Вызов: [TASK_ID, {TITLE: "текст работы"}] для каждой работы
• [!] критичные → {TITLE: "⚠ работа", IS_IMPORTANT: "Y"}
Переменные шаблона:
{TO_NAME}, {SITE_NAME}, {GEN_NAME}, {HOURS}, {RESPONSIBLE}
Исходящий вебхук (обратная связь):
Б24 → SCADA: при закрытии задачи → обновить статус ТО.
Настройка: Б24 → Разработчикам → Исходящий вебхук → Событие: ONTASKCOMPLETE
